# マイ図鑑 — GitHub Pagesへ置ける完成パッケージ

23名分の生徒用フォルダと完成例を収録しています。アカウント作成や外部公開はまだ行っていません。

## まず起動する

- このフォルダ全体を展開し、ルートの `index.html` をダブルクリックします。
- 完成例は `examples/demo/index.html`、実習は `students/s01/index.html` などを開きます。
- Chrome/Edge + vscode.devでローカルフォルダを編集し、Ctrl+S → 実行画面を再読み込み。
- npm・ビルド・サーバー・追加ソフト・外部CDNは不要です。

## GitHub Pagesで公開する

教員自身のアカウントでリポジトリを用意し、この `github-ready` **フォルダの中身**を
リポジトリ直下にコミットします。フォルダ名ごと一段深く置かないようにします。
Settings → Pages → Deploy from a branch → main / (root) → Save。
公開例は `https://ACCOUNT.github.io/my-collection-class/students/s01/` です。
ACCOUNTとリポジトリ名は実際のものに置き換えます。

GitHubの1ログインを複数人で共有しない運用にしています。生徒は担当フォルダを教員へ提出し、
教員がまとめて反映します。生徒が直接アップロードする場合は各自のアカウントを使います。
フォルダ分けはアクセス権の分離ではありません。
GitHubのWebアップロードは1回100ファイルまでのため、初回は3〜5人ずつなどに分けます。
詳しい手順は付属の教員用運用資料を参照してください。

## フォルダ構成

- `index.html` 生徒用フォルダの一覧
- `.nojekyll` 静的ファイルをそのまま配信するための指定
- `.gitignore` ローカルSQLiteバックアップなどを誤って含めにくくする指定
- `assets/vendor/` 全フォルダ共通のsql.js 1.13.0とライセンス
- `examples/demo/` 完成例（おすすめ度を星で表示）
- `students/s01/` 〜 `students/s23/` 生徒用ひな型（おすすめ度を数字で表示）

各アプリ内のREADME.mdにソースの役割・保存のしくみ・変更ポイントを記載しました。
SQLファイルは `sql/`、初期表示/公開用データは `data/collection-data.js` です。
**一人分のフォルダだけを配布せず、共通vendorを含むこの全体を配布してください。**

## できること

登録・編集・削除、タイトル/メモの検索、分類の絞り込み、おすすめ順等の並べ替え、
6種類の同梱カバー、ブラウザ内への保存、SQLiteバックアップの入出力、
公開用collection-data.jsの書き出し、独立したDBでのSQL演習。
本物のSQLiteエンジン（sql.js asm.js版）を使っています。

## 公開データの提出

1. 公開してよい内容だけに整え、念のためSQLiteを保存します。
2. 「公開用データを書き出す」でcollection-data.jsをダウンロードします。
3. 自分の `students/sXX/data/collection-data.js` と同名で置き換えます。
4. 自分のsXXフォルダを教員へ提出します。SQLiteバックアップは公開フォルダへ入れません。
5. 教員がリポジトリ内の同じ場所へ反映します。

既存のブラウザ保存がある場合は、SQLiteバックアップ後に「配布データに戻す」で公開内容を
確認します。別ブラウザの初回アクセスでも確認できます。
GitHub Pagesは共有DBサーバーではなく、見た人のブラウザでSQLiteが動きます。
ブラウザの変更だけでGitHubや他の端末が更新されることはありません。
